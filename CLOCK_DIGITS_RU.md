# Золотые цифры часов на главном экране B220

Найдены и извлечены именно золотые цифры главного экрана. Это **11 отдельных
картинок ABMP**, а не символы четырёх заменённых таблиц шрифта.
Набор включает 0…9 и двоеточие. Новые шрифты K550i/Arial Narrow его не меняют.
Исследование не изменяет прошивку и не добавляет сглаживание обычному тексту.

Вход — исходный PS, SHA-256
`7bd1dd7b3ce3a3efa65f957eb24e4e4b3114775c8b7770121f98b39816bacbeb`.
Адреса ниже — смещения в этом raw PS и одновременно ROM-адреса при базе 0.

| Знак | Адрес ABMP | Размер ячейки | Байтов ABMP | Значений частичной прозрачности |
|---|---|---|---:|---:|
| 0 | `0x345C0` | 13×28 | 548 | 89 |
| 1 | `0x347E4` | 13×28 | 312 | 37 |
| 2 | `0x3491C` | 13×28 | 528 | 86 |
| 3 | `0x34B2C` | 13×28 | 578 | 99 |
| 4 | `0x34D70` | 13×28 | 388 | 51 |
| 5 | `0x34EF4` | 13×28 | 450 | 70 |
| 6 | `0x350B8` | 13×28 | 584 | 101 |
| 7 | `0x35300` | 13×28 | 466 | 65 |
| 8 | `0x354D4` | 13×28 | 610 | 110 |
| 9 | `0x35738` | 13×28 | 576 | 102 |
| : | `0x35978` | 4×16 | 142 | 28 |

Сумма размеров — **5182 байта**, занимаемый диапазон с межресурсным
выравниванием — **5190 байт**, `0x345C0…0x35A05` включительно.
В ROM по `0x72D334` найден указатель на начало набора `0x345C0`.
Отображение и выбор конкретной цифры установлены по извлечённым рисункам;
полный механизм индексирования ресурсной группы пока не разобран.

## Формат ABMP для этого набора

Это собственный формат Spreadtrum, не обычный BMP и не монохромный шрифт.
Значения многобайтовых полей — big-endian.

| Смещение от ABMP | Поле |
|---|---|
| `+0` | ASCII `ABMP`, четыре байта |
| `+4`, `+6` | Ширина и высота ячейки, u16 |
| `+8` | Граница индексов непрозрачных цветов, u16; здесь 2 |
| `+10` | Количество полупрозрачных записей, u16 |
| `+12…+15` | Пустые поля сверху, слева, снизу, справа, по одному байту |
| `+16` | Палитра RGB565: `(opaque_limit + alpha_count - 1)` слов u16 |
| После палитры | `alpha_count` байтов непрозрачности, с выравниванием до двух байт |
| После alpha | Упакованные индексы пикселей активного прямоугольника |

Индекс 0 означает полностью прозрачный пиксель и не занимает запись палитры.
Индекс 1 в этом наборе — непрозрачный цвет. Последующие индексы задают пару
«цвет из палитры + непрозрачность из alpha-таблицы». Во всех записях этих
11 ресурсов цвет одинаковый: **RGB565 `0xFF55`**, RGB при обычном расширении
битов **(255, 235, 173)**. Поэтому плавные края создаются именно alpha,
а не набором заранее затемнённых цветов.

Для цифры 0 имеются один непрозрачный вариант и **89** частично прозрачных,
с alpha от 1 до 254. Все 89 реально используются пикселями. Индексы занимают
7 бит. У других цифр — 6 или 7 бит, у двоеточия — 5 бит.

Особенность упаковки: слова читаются как **u16 big-endian**, но биты индексов
потребляются от младших к старшим внутри каждого слова. Индекс может пересекать
границу слова. Строки идут подряд, без отдельного выравнивания каждой строки.
Активная область исключает поля, указанные в заголовке. Например, у 0 поля
сверху 4, снизу 1, по бокам 0; активный прямоугольник — 13×23 внутри 13×28.

## Штатное смешивание с фоном

В исследованном состоянии ARM-функция выполняется по **`0x40002800`** в SRAM;
её исходные байты найдены в PS по **`0x744F70`**. Реальный вызывающий адрес
при перерисовке часов — **`0x62848C`**.

Внутри есть отдельные ветки для прозрачных, непрозрачных и полупрозрачных
пикселей. Полупрозрачная ветка читает RGB565 фона, смешивает его с цветом
источника и записывает результат. В арифметике используется вес
`alpha` и обратный вес `256-alpha`; округление соответствует коду прошивки.
Нативные инструкции смешивания: **`0x40002A30…0x40002AC0`**.

Это подтверждённый готовый alpha-композитор в прошивке. Наш прежний вывод
об однобитном пути обычных букв остаётся верным; утверждать отсутствие
сглаживания во всей графической системе было бы неверно. В будущем этот
графический путь может пригодиться для букв, но интеграция с текстовыми
метриками и формат хранения новых наборов — отдельная работа, сейчас отложенная.

## Доказательство и воспроизведение

Инструмент: `tools/research_clock_digits.py`. Он только читает исходный PS,
выгружает ресурсы и при `--observe` запускает отдельную плату из совместимого
снимка SD APP. Используются настоящие события клавиатуры: меню, затем красная
клавиша возврата на главный экран. Хостовые записи в регистры/код/RAM гостя
не применяются; текущее окно пользователя не затрагивается.

Наблюдались четыре вызова ресурса 0 и один вызов двоеточия при показе `00:00`:
цифры в координатах (9,165), (23,165), (43,165), (57,165), двоеточие — (37,177).
Все пиксели пяти прямоугольников в гостевом графическом буфере **точно совпали**
с результатом нашего декодера и восстановленной RGB565-арифметики.
Цифры 1…9 также извлечены и визуально распознаны, но динамический тест с
переводом часов во все десять значений не выполнялся.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m tools.research_clock_digits
.\.venv\Scripts\python.exe -X utf8 -B -m tools.research_clock_digits --observe
```

В `analysis/clock-research/`:

- `clock-0.png`…`clock-9.png`, `clock-colon.png` — RGBA PNG с прозрачностью.
- `clock-*-black.png` — расчёт штатного RGB565-смешивания поверх чёрного фона.
- `clock-digits.png` — все 11 ресурсов, увеличение 3×.
- `clock-00-05.png` — пример `00:05`, собранный на ПК из найденных ресурсов, 4×.
- `clock-resources.json` — заголовки, палитры, alpha, адреса и результаты наблюдения.

В основном PS также обнаружены другие ABMP, включая отдельный набор картинок
размером 28×44. Их назначение этим исследованием не устанавливается.
