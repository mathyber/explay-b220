# Платформа Spreadtrum MOCOR и открытые материалы

## Что за платформа

MOCOR — программная платформа Spreadtrum (с 2018 года — Unisoc) для кнопочных
телефонов. Spreadtrum отдавала её дизайн-хаусам готовым комплектом по лицензии и
NDA:
- ОС со своим слоем API (`SCI_…`). Своего ядра у MOCOR нет, обычно под ней
  ThreadX; по прошивке B220 ядро не определить.
- Стек GSM/GPRS, драйверы.
- Интерфейс MMI (модули `MMIAPISET_…`, `MMIAPICC_…`, `mmiapp.c`).
- Инженерное меню, формат прошивки `.pac`, прошивальщик (SPD Upgrade Tool,
  Research Download).

Дизайн-хаус перекрашивал интерфейс, раскладывал меню, добавлял языки и
приложения, назначал свои сервисные коды и продавал телефон брендам.

### Что сказано в прошивке B220

| Строка | Значение |
|---|---|
| `Platform Version: MOCOR_09A.W10.25.16.04_Debug` | MOCOR 09A, сборка 25-й недели 2010 года, **отладочная** (`_Debug`). Поэтому в прошивке так много отладочных строк с именами функций |
| `BASE_10A.W11.24.02` | базовая часть (стек, драйверы), середина 2011 года |
| `MOCOR.TCPIP_09A_101117` | модуль TCP/IP от 17.11.2010 |
| `Platform\KUNLUN3_1026\MS_PLD\6800_Platform\SW\ProductAdvanced\MMI_Ap…` | путь исходников: проект KUNLUN3, ветка платформы SC6800 (SC6600L в неё входит) |
| `Spreadtrum Boot Block version 3.0` | загрузчик |

### Насколько платформа единая

Общее у телефонов на одном семействе чипов и близкой версии MOCOR:
- имена модулей и функций в отладочных строках, устройство MMI и окон;
- номера настроек NV (группы вроде 0x0d из [SECRET_CODES_RU.md](SECRET_CODES_RU.md));
- инженерное меню «Eng Mode»;
- `*#06#` и таблица языков по коду страны;
- формат прошивки и инструменты прошивки.

У каждой модели своё:
- **адреса**: каждая прошивка собрана отдельно, функции лежат в других местах;
- сервисные коды дизайн-хауса, языки, ресурсы, приложения, железо.

Поздние чипы (SC6530/SC6531, MOCOR 2012–2013 годов) уже заметно отличаются.

Что это значит для проекта:
- Знания о B220 переносятся на соседние телефоны с SC6600L и MOCOR 09A.
- Патчи не переносятся: загрузчик GO1 и вставки вызывают функции прошивки по
  адресам (`FN(0x…)`). Для другого телефона адреса нужно найти заново, в этом
  помогут те же отладочные строки.
- Программы с карты (`JAVA.GO1`, браузер) работают через API загрузчика и после
  переноса загрузчика пошли бы без изменений.

## Исходники

Официально исходников MOCOR нет. По слухам, исходники и SDK разных версий
утекали (чаще для SC6530/SC6531), но это чужой закрытый код. Проект его не
использует и не ищет.

## Открытые материалы (поиск 2026-11-08)

Почти всё — про более новые SC6530/SC6531; SC6600L нигде прямо не
поддерживается.

### Прошивка и дамп флеша

Все инструменты работают через загрузочный режим: зажатая клавиша при
подключении USB, устройство 1782:4d00, затем в телефон загружаются FDL1/FDL2.
FDL — загрузчик флеша из прошивки: FDL1 поднимает внешнюю RAM и загружает FDL2,
а FDL2 умеет всё остальное.

- [spreadtrum_flash (`spd_dump`)](https://github.com/ilyakurdyukov/spreadtrum_flash),
  Илья Курдюков. Дамп флеша кнопочных SC6530, SC6531DA, SC6531E и 4G-моделей
  (UMS9117 и родственные). SC6600L в списке нет. В README есть список смежных
  проектов: исходники SPD Flash Tool, sharkalaka, uwpflash, sprdproto, bzpwork,
  unisoc_dloader.
- [UniFlash](https://code.luxferre.top/luxferre/uniflash) (Luxferre, Python, public
  domain, кроме FDL) — чтение и запись флеша старых кнопочных Unisoc/Spreadtrum.
  Предупреждает: неверная длина дампа и запись из него могут сделать телефон
  незагружаемым.
- [Opus Spreadtrum](https://archive.luxferre.top/chronovirus/2021/12/18/Opus-Spreadtrum) —
  разбор протокола загрузчика: HDLC-кадры, CRC, команды. Протокол у поколений
  почти общий.
- [sfd_tool](https://github.com/C-Hidery/sfd_tool) — `spd_dump` с GUI. Для
  смартфонов, нам не подходит.

### Разбор `.pac`

- [upac](https://github.com/ersascape/upac) — чтение заголовков и таблицы файлов,
  извлечение, XML со схемой прошивки.
- bzpwork — упаковка и распаковка, ссылка в списке spreadtrum_flash.

Прошивку B220 проект уже разбирает сам (`run_analysis.ps1`).

### Свой код на телефоне без перепрошивки

[FPDoom](https://awesome.ecosyste.ms/projects/github.com%2Filyakurdyukov%2Ffpdoom)
запускает Doom на SC6530/SC6531: через `spd_dump` загружает свою программу
вместо FDL прямо по USB, флеш не трогается. Подробно —
[статья автора на Хабре](https://habr.com/en/articles/701276).

### Исследования безопасности

- [NCC Group: уязвимости загрузочного ROM Unisoc](https://nccgroup.com/research-blog/there-s-another-hole-in-your-soc-unisoc-rom-vulnerabilities).
- [ONEKEY: обход защиты MOCOR через fault injection](https://onekey.com/blog/security-advisory-unisoc-mocor-fault-injection-security-bypass).

Обе работы про новые чипы. Они подтверждают, что у MOCOR нет своего ядра (обычно
ThreadX) и что платформа стоит в телефонах Nokia, TCL, Alcatel и других.

### Документация на чипы

На SC6600L ничего не найдено. Есть интерфейсная спецификация на родственный
[SC6600M](https://share.eepw.com.cn/share/download/id/93465) (2006 год, с пометкой
«Confidential»). Формат NV публично не описан; резервные копии NV делают
Research Download и платные комплексы (файлы `.spdnv`).

## Что из этого полезно проекту

1. **Резервная копия флеша B220** перед экспериментами с прошивкой: `spd_dump` или
   UniFlash с FDL из нашего `.pac`. Вероятно, понадобятся правки под SC6600L.
2. **Протокол загрузчика** (Opus Spreadtrum): можно научить эмулятор загрузочному
   режиму или написать свой загрузчик.
3. **Приём FPDoom** — свой код по USB без перепрошивки. Так можно безопасно
   измерить реальную скорость телефона (`BENCH.GO1`, JIT), когда он будет на руках.
