# Узкий шрифт в отдельной прошивке B220

Запуск: **`Start B220 FONT.cmd`**. Он собирает эксперимент и открывает его
в обычном окне эмулятора. Внутри экрана телефона рисует сама прошивка;
подмена текста средствами окна Windows не используется.

За основу взят текущий вариант с выбором приложений с SD:
`analysis/firmware-patches/sd-app/sd-app.bin`, SHA-256
`b9da6a50a6c8a0c66d3f1d7e28107b28949d86aee47519c456a57cfa551eb104`.
Для нового варианта подготовлена своя карта с DEMO.B22 и SECOND.B22.
Основная NOR/SD и исходный PS не перезаписываются. Перекрашивание скроллбара
остаётся отдельным экспериментом GREEN; при желании можно явно взять его
образ через `--source`.

## Что заменено

На компьютере растрируется установленный **Arial Narrow**, файл
`C:\Windows\Fonts\ARIALN.TTF`. Его имя и SHA-256 записываются в манифест.
Сам TTF не копируется в репозиторий и не загружается в телефон.

| Параметр | Было | Стало |
|---|---:|---:|
| Высота ячейки, режимы 4/6 | 16 | 14 |
| Высота ячейки, режим 3 | 14 | 12 |
| Размер исходного TTF при растеризации | — | 12 / 10 |
| Ширина кириллической О, большой набор | 10 | 8 |
| Ширина латинской O, большой набор | 11 | 8 |
| Ширина пробела, большой набор | 8 | 3 |

Высота ячейки включает место над буквами и под строкой. Видимый рисунок обычной
прописной буквы ниже полной высоты; Ё/Й и нижние выносные элементы используют
это пространство. Цель первого варианта — существенно более плотный текст.
Макет меню, интервалы между пунктами и размеры кнопок отдельно не менялись.

Изменены четыре найденных набора: латиница/знаки и кириллица, по два размера.
Все русские буквы взяты из нового шрифта. Для редких расширенных символов,
отсутствующих в выбранном TTF, уменьшен исходный растр. Это отмечено полем
`fallback` для каждого символа. В текущем Arial Narrow таких позиций 161
в каждом расширенном кириллическом наборе и две в каждом компактном наборе
(угловые скобки U+300A/U+300B); обычный русский алфавит заменён полностью.

Надписи внутри картинок и другие неразобранные наборы этим патчем не меняются.
Тексты наших программ, использующие штатный режим 6, получают новый шрифт.
Вёрстка некоторых экранов может съехать — на этом этапе это допускается.

## Как устроен патч

Каждый растр занимает только исходный слот `ceil(old_width * old_height / 8)`.
Новая ширина не превышает исходную, новая высота также меньше. Остаток слота
обнуляется. Смещения глифов и указатели на наборы сохраняются. Хвосты,
выравнивание, терминаторы и промежутки между таблицами не используются.
Границы и SHA-256 исходных блоков проверяются перед заменой.

Формат — 1 bpp, старший бит первым, без выравнивания каждой строки на байт.
Полутонового сглаживания нет. Сначала TTF растрируется в однобитный рисунок,
затем он упаковывается в этот родной формат. Если редкий знак выходит за
ячейку, весь его рисунок вписывается в доступное место.

Две Thumb-инструкции штатной функции высоты `0x5B870C` изменены:

- `0x5B8716`: `MOVS r0,#16` → `MOVS r0,#14`.
- `0x5B871E`: `MOVS r0,#14` → `MOVS r0,#12`.

Другие инструкции не меняются. Сборщик проверяет все отличающиеся байты.
Повторное применение к уже заменённым таблицам отвергается.

## Результаты и проверка

Под `analysis/firmware-patches/narrow-font/` находятся:

- `source-copy.bin` — точная копия образа до замены.
- `b220-narrow.bin` — образ для эмулятора.
- `manifest.json` — метрики, источник, хеши и сведения о каждом глифе.
- `comparison.png` — сравнение исходных и новых растров, прочитанных из ROM.
  Это иллюстрация плотности текста, не снимок экрана эмулятора.
- `proof.json` — результат проверки через настоящий машинный код прошивки.
  При запуске с `--boot` также содержит результат независимой загрузки.
- `native-menu.png` — единственный итоговый кадр дополнительного прогона `--boot`.

Проверка API выполняет 1194 вызова штатного получения дескриптора символа
`0x4CDC00`: все 398 символов для режимов 3, 4 и 6. Проверяются настоящий
Unicode-индекс, указатель на растр, ширина, высота и корректный возврат.
Также проверяется публичная функция высоты `0x4CDCC4`. Этот тест использует
прямые вызовы с подготовленными регистрами и начальной RAM; он отдельно
обозначен как тест интерфейса и не выдаётся за загрузку телефона.

Дополнительный `--boot` загружает независимую плату с нуля, нажимает настоящие
кнопки через KPD, сохраняет один кадр меню и считает обращения к изменённой
функции высоты. Регистры и RAM этого прогона с хоста не подменяются.

Первый прогон выполнен успешно: пять тестов PASS, 1194 дескриптора PASS,
независимая загрузка и переход в «Мультимедиа» PASS. На итоговом кадре виден
новый узкий текст. За прогон отмечены 1013 вызовов большого и 42 малого пути
высоты. Образ после замены имеет SHA-256
`1d5add8eadbffe6a8bdb97d019327bc03b049d819a0f72478f5cb814b67fdd12`.
Исходный SD APP PS сохранил прежний хеш. Результат не означает проверки всех
экранов: выравнивание и размеры отдельных элементов пока не адаптировались.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m tools.build_font_patch --prepare-card
.\.venv\Scripts\python.exe -X utf8 -B -m tools.prove_font_patch
.\.venv\Scripts\python.exe -X utf8 -B -m tools.prove_font_patch --boot
.\.venv\Scripts\python.exe -X utf8 -B -m unittest tests.test_font_patch -v
```

Размеры можно менять параметрами `--large-height` и `--small-height`.
`--font` выбирает другой местный TTF/OTF с латиницей и русскими буквами.
По умолчанию размер растеризации равен высоте ячейки минус два пикселя.
Для другого эксперимента задавайте отдельный `--directory` и сохраняйте
использованный шрифт локально: одинаковое имя шрифта на разных ПК не гарантирует
совпадение рисунков, поэтому в манифест записан хеш файла.
