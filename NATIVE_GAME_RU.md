# Нативная игра на C в прошивке B220

«Поймай!» / **Catch the dot** — первая небольшая самостоятельная программа
для этого образа. Голубой квадрат двигается по полю 8×7, жёлтый — цель.
При совпадении прибавляется очко и появляется следующая цель.

Игра выполняется ARM/Thumb-процессором вместе с прошивкой. Её C-код вызывает
штатные функции рисования; изображение поступает через обычный LCD-контроллер.
Кнопки проходят через KPD/IRQ и диспетчер окон MMI.

## Запуск

Дважды щёлкните **`Start B220 GAME.cmd`**. Он собирает отдельный raw PS
`analysis/firmware-patches/game/catch-game.bin` и открывает обычное окно эмулятора.
На первом запуске при отсутствии компилятора скачивается официальный Zig 0.13.0
для Windows x64, около 79 МБ. Скрипт проверяет закреплённый SHA-256 архива.
Компилятор и его кеш остаются в `analysis/toolchains/`, вне Git.

На новой NOR подтвердите дату и время левой экранной клавишей. Затем:

**Меню → Мультимедиа → Игры → Поймай! → Новая игра.**

В английском интерфейсе название — `Catch!`. Обычный `Start B220.cmd`
запускает исходную прошивку; `Start B220 MOD.cmd` оставлен для предыдущего
эксперимента с заголовком времени. Для каждого изменённого PS окно выбирает
собственные сохраняемые NOR и карту памяти по SHA-256.
Сетевой HLE пока разрешён только для исходного PS.

Управление:

- Стрелки или `2`, `4`, `6`, `8` — движение без перехода через края поля.
- Enter / центральная OK — начать заново.
- Правая экранная / F2 — выйти в меню игры.

Счёт от `000` до `999`, затем снова `000`. При повторном входе начинается
новая партия. Пункт штатного меню «Продолжить» тоже начинает новую партию:
сохранение нашей игры пока не реализовано. Эмулятор выполняет прошивку медленнее
настоящего телефона; во время загрузки и переходов между меню нужно подождать.

## Сборка

```powershell
.\.venv\Scripts\python.exe -m tools.setup_arm_toolchain
.\.venv\Scripts\python.exe -m tools.build_catch_game
```

Исходники: [игра](patches/catch_game.c), [размещение](patches/catch_game.ld),
[сборщик](tools/build_catch_game.py).

Используется freestanding C, без libc, кучи и внешнего рантайма. Цель компиляции:
`thumbeb-freestanding-eabi`, `arm7tdmi`, `-Oz`. ARMv4T выбран как ограничение
набора инструкций; соответствие физическому CPU ещё предстоит проверить.
Существенен именно `thumbeb`: с прежним `armeb` этот драйвер выдавал ARM-код
несмотря на `-mthumb`. Вход задаётся явно `-e game_handler`; сборщик проверяет
ELF32 big-endian ARM, Thumb-бит входа, границы секции и отсутствие релокаций.
Линкер запрещает ненулевую `.bss`.

Дистрибутив и контрольная сумма закреплены по
[официальному каталогу Zig](https://ziglang.org/download/index.json).
`setup_arm_toolchain` не требует изменения PATH или установки в систему.

## Как программа встроена

Штатное окно Сокобана использовано как оболочка с готовыми пунктами меню,
экранными клавишами и обработкой закрытия. Старый обработчик `0x60f74f`
остаётся в ROM. В четырёх дескрипторах заменяется указатель на наш обработчик:
`0x70d154`, `0x70d198`, `0x70d1dc`, `0x70d220`.

| Область | Использование |
|---|---|
| ROM `0x14d000` | Thumb-код и константы, вход `0x14d001` |
| ROM до `0x152f2a` | Верхняя граница выделенного места под программу |
| RAM `0x04388f50`, 32 байта | Состояние игры в первых 32 байтах прежней доски Сокобана из 81 байта |
| JPEG `0x14c528`, 27155 байт | Один встроенный фон заменён однотонным JPEG; код расположен после его EOI |

Размер PS сохраняется. Исходный PS проверяется по SHA-256. Все изменения
перечислены в `manifest.json`; прежние патчи клавиши и надписи `B220 MOD`
входят в этот вариант. Нативная метка при `0x152f2a` сохранена.
Исходный архив и извлечённые PS/NV не перезаписываются.

При открытии `0xf021` сначала вызывается старый обработчик, который готовит
окно и штатную игровую память. Затем эта память используется нашим состоянием.
Сообщения перерисовки `0xf024`, `0xf025`, `0x40000014` рисуют наше поле.
Нажатия стрелок `0xfa01…0xfa04`, цифровые сообщения и OK обрабатываются своим
кодом; старая логика перемещения и отмены хода не получает изменённую доску.
Закрытие и остальные служебные события передаются старому обработчику.

Установленные вызовы графики для этого PS:

| Thumb-указатель | Назначение и параметры |
|---|---|
| `0x4c65ad` | Заливка: `R0={lcd_id,layer_id}`, R1/R2 — углы, R3 — RGB565 |
| `0x4cf433` | Текст: R0 — тот же контекст устройства, R1/R2 — углы, R3 — UTF-16 BE; далее длина, параметры цвета/шрифта/выравнивания |
| `0x4c5b69` | Изменение текста штатного label; используется для очистки старого индикатора уровня |

Углы упакованы как `(x << 16) | y`, границы включительные.
Заливка занимает рабочие 176×196 пикселей; нижняя полоса остаётся для штатной
экранной клавиши «Выход». Отдельный вызов flush не добавлен: обновление LCD
происходит при возвращении из обработки сообщения MMI.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_catch_game_patch tests.test_ui_label_patch tests.test_firmware_patch
.\.venv\Scripts\python.exe -m tools.prove_catch_game --directory analysis/firmware-patches/game/proof-final
.\.venv\Scripts\python.exe -m tools.verify_artifacts
```

`prove_catch_game` начинает с холодной загрузки именно нового PS. Дальше только
подаёт нажатия через модель клавиатуры и наблюдает выполнение; регистры, RAM
и код гостя проверочный инструмент не подменяет. Каждый шаг сохраняет LCD,
снимок состояния и сведения о вызовах MMI.

Локальный прогон завершён с **PASS**: 27 нажатий, 36 входов в наш обработчик,
включая выход и повторное открытие. Размер кода и констант — 1352 байта,
состояния — 32 байта. SHA-256 проверенного PS:
`cf45d190dc77ab8cec0ec30d03ccc6c224c770dbd750b549c69ab72685acc7a7`.

Проверяются открытие через штатное меню, исполнение нашего Thumb-входа,
движение стрелками, первое очко, OK, все четыре цифровые клавиши, остановка
на левом краю, выход и повторное открытие. В конце хеш CPU-видимого PS
сравнивается с выбранным образом. Отдельные тесты проверяют границы изменений,
JPEG, сохранение прежней метки и отказ при неверном образе/ELF/переполнении.

Артефакты создаются локально и не входят в Git:
[манифест](analysis/firmware-patches/game/manifest.json),
[отчёт](analysis/firmware-patches/game/proof-final/proof.json),
[первое очко](analysis/firmware-patches/game/proof-final/11-right.png),
[игра после повторного входа](analysis/firmware-patches/game/proof-final/26-ok.png).

Открыть уже полученный снимок сразу на игре:

```powershell
powershell.exe -NoProfile -STA -File emulator/window.ps1 -Firmware analysis/firmware-patches/game/catch-game.bin -LoadState analysis/firmware-patches/game/proof-final/26-ok.b220state
```

Снимок открывается на паузе: нажмите «Продолжить». После изменения C-кода или
модели эмулятора снимок нужно получить заново; совместимость проверяется при загрузке.

Это проверка в эмуляторе. На физическом B220 программа пока не запускалась.
Адреса привязаны к этой версии PS и не составляют универсальный SDK.
Следующий шаг — выделить проверенные вызовы в маленький интерфейс приложений,
затем добавить таймер и доступ к файлам карты. Путь к J2ME потребует отдельно
выбрать и разместить Java-машину и реализовать необходимые CLDC/MIDP API.
