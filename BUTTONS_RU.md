# Кнопки Explay B220 в эмуляторе

В окне есть все 23 клавиши с фотографии: две экранные, четыре направления и
центральная OK, три зелёные клавиши вызова, красная завершения/питания,
цифры, `*` и `#`. Запуск — прежний `Explay B220.lnk` или `Start B220.cmd`.
Закройте старое окно и запустите заново, чтобы загрузить новую версию.

Нажимайте мышью или используйте клавиатуру компьютера:

| На телефоне | На компьютере |
|---|---|
| Направления | Стрелки |
| Центральная OK | Enter |
| Левая / правая экранная | F1 / F2 |
| Зелёная SIM 1 / SIM 2 / SIM 3 | F5 / F3 / F4 |
| Красная завершения / питания | Esc или End |
| Цифры | 0–9 сверху или NumPad |
| Звёздочка | NumPad `*` или Shift+8 |
| Решётка | NumPad `/` или Shift+3 |

Каждая кнопка имеет подсказку при наведении. Удержание мыши и клавиши
передаёт отдельные нажатие и отпускание; автоповтор Windows не создаёт
повторных нажатий. При потере фокуса все удерживаемые клавиши отпускаются.
Одновременные нажатия пока сериализуются, аппаратный rollover не воспроизведён.

Загрузка занимает примерно 1–1,5 минуты на этом компьютере. После начальных пяти
полных перерисовок эмулятор даёт прошивке ещё 512000 блоков на открытие
первого окна, затем ставит CPU на паузу. Это выбранная контрольная точка,
не измерение частоты настоящего процессора. Первое нажатие автоматически
продолжает выполнение. Кнопка «Пауза» позволяет остановить CPU вручную.
При первом запуске могут появиться настройка даты и времени: подтвердите
каждую левой экранной клавишей, затем ещё раз нажмите её для открытия меню.
Экран обновляется по мере исполнения; первое открытие меню с картинками может
занимать десятки секунд. Дождитесь перерисовки. Это пока медленнее настоящего телефона.

Сессия сохраняет живые CPU и RAM между нажатиями. При закрытии или перезапуске
сохраняется виртуальная NOR в `analysis/emulator/window-nor-v2.bin`, следующий
запуск загружается заново. Исходные ZIP, PAC, PS и NV остаются неизменными.
Консольный `run_emulator.ps1 -Frames 5` по-прежнему делает отдельный конечный
прогон для исследования, без интерактивной панели.

## Как подключён ввод

Обработчики MMI не подменяются. Нажатие проходит через регистры периферии,
настоящее ARM-прерывание, обработчик прошивки и её очередь `T_KPDSVR`.

* Матрица: `0x87000000`, IRQ8, первичный обработчик PS `0x5b407a`.
  Enable `+04`, masked status `+08`, raw `+0c`, W1C `+10`, координаты `+2c`.
  Один слот: строка в bits0..2, столбец в bits4..6, bit3 — состояние
  отпускания; down вызывает bit0, up — bit4 в статусе IRQ.
* Таблица матрицы: PS `0x3dd46c`, 64 значения u16 BE.
  Навигация даёт native-коды 4/5/6/7, OK — `0x0d`, экранные — 8/9,
  вызовы SIM1/2/3 — 1/`0x1a`/`0x1b`, цифры — ASCII.
* Красная кнопка отсутствует в матрице. Это GPIO3: данные `0x8a000000`,
  enable `+18`, pending `+20`, W1C `+24`, IRQ6. Оригинальный callback
  PS `0x3a7d68` передаёт `0x2002`, а MMI получает native-код 2.
  Короткое нажатие возвращает из меню на домашний экран. Другие GPIO-входы
  остаются статическими; это частичная модель порта.
* Отложенный обработчик `0x1f6cac` отправляет down/up в `T_KPDSVR`.
  Наблюдатель `0x1a1236` только журналирует аргументы callback MMI,
  не меняя гостевой код, регистры или память.
* Для переходов между окнами добавлен встреченный RAM→RAM DMA канала 16:
  конфигурация `0x0a80xxxx`, stride `0x00040004`, frame increments 4.
  Назначение ограничено RAM, запись в исходную прошивку запрещена.
* Остановка по кадрам теперь выполняется на следующей границе блока CPU.
  Возобновление не повторяет последнюю запись запуска LCD DMA.

Между WinForms и Python используется отдельный для каждого запуска JSONL
канал. Команды проверяются, незавершённые строки дочитываются следующим
опросом. CPU выполняется короткими порциями, поэтому ввод, пауза и закрытие
обрабатываются без перезапуска прошивки.

## Проверка

Модульные проверки включают порядок down/up, маски и W1C, отдельный GPIO
красной клавиши, отпускание при потере фокуса, соответствие клавиш таблице
оригинальной PS, разорванные команды и границы RAM DMA.

Прогон `powershell -NoProfile -ExecutionPolicy Bypass -File emulator/window.ps1 -KeyTest`
открывает настоящее окно и проверяет экранные кнопки и обработчики клавиатуры:
настройку даты/времени при необходимости, меню, перемещение вправо с изменением
изображения, выход красной кнопкой, ввод `12`, паузу/продолжение и закрытие
дочернего процесса. Он читает пользовательскую NOR, но не перезаписывает
её. Результат — `analysis/emulator/window-key-check.json`, журнал —
`analysis/emulator/window-key-test.html`, снимки — `window-key-stage-1..5.png`.

Это ввод для исследовательского эмулятора. Звонки, модем, сеть, звук и все
остальные устройства этим изменением не реализованы. Полный сценарий
длительного удержания питания и выключения ещё не проверен.
