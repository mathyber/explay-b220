# Программы с карты памяти

Модифицированная прошивка содержит небольшой интерпретатор **B22V v1**.
Программы лежат отдельными файлами **`E:\*.B22`** на карте памяти. Список
**`E:\APPS.LST`** содержит их имена. Прошивка показывает выбор приложения,
открывает выбранный файл штатным SFS, читает в выделенную ею RAM, закрывает
файл и выполняет байткод.
Чтение FAT16 и секторов проходит через драйвер телефона, SPI/DMA и модель SD.
В эмуляторе не добавлено обработчиков файловых вызовов или исполнения B22V.

Такой формат выбран для первого работающего загрузчика: он не требует
загрузки ELF, переноса адресов ARM или размещения Java-машины. У программы
есть восемь регистров, арифметика, условные переходы, рисование и события клавиш.
JAR/J2ME пока не поддерживаются.

## Запуск

Дважды щёлкните **`Start B220 SD APP.cmd`**. Скрипт собирает загрузчик в отдельный
`analysis/firmware-patches/sd-app/sd-app.bin`, при необходимости создаёт его
виртуальную карту с двумя демонстрационными программами и открывает обычное окно.
Если компилятора ещё нет, скачивается закреплённый Zig, как для нативной игры.
Уже установленные программы обычный запуск сохраняет.

В телефоне откройте **Мультимедиа → Игры → SD Apps**.
На свежей NOR сначала подтвердите дату и время.

Сразу открывается список файлов, без меню «Новая игра»:

- Стрелки вверх/вниз выбирают приложение, OK запускает.
- Изначально на карте одновременно лежат `DEMO.B22` и `SECOND.B22`.
- Поддерживаются до 16 приложений, по 6 строк на странице.
- F1 в списке перечитывает каталог, F2 закрывает список.

В демонстрационной программе:

- Стрелки двигают голубой квадрат.
- OK возвращает его в начальную позицию.
- Левая экранная / F1 перечитывает файл и сбрасывает состояние программы.
- Правая экранная / F2 освобождает буфер приложения и возвращает к списку.

## Добавить или обновить программу без изменения прошивки

Закройте окно эмулятора и выполните:

```powershell
.\.venv\Scripts\python.exe -m tools.install_sd_app apps/card_second.b22asm
```

Затем снова запустите **`Start B220 SD APP.cmd`** и откройте SD Apps.
В списке выберите `SECOND.B22`: программа покажет надпись **SECOND SD APP**
и красный прямоугольник. Первая программа остаётся в `DEMO.B22` на той же карте.
PS остаётся тем же; изменяются только файл приложения и каталог на карте.

Обновить первую программу:

```powershell
.\.venv\Scripts\python.exe -m tools.install_sd_app apps/card_demo.b22asm
```

Свою программу установите той же командой, указав свой `.b22asm`. Имя файла
получается из имени исходника; у примеров отбрасывается префикс `card_`.
Можно задать его явно:

```powershell
.\.venv\Scripts\python.exe -m tools.install_sd_app apps/my_program.b22asm --name MYAPP.B22
```

Допустимы имена ASCII 8.3: 1…8 букв A–Z, цифр или `_`, расширение `.B22`.
При совпадении имени обновляется только соответствующее приложение.
Утилита пересобирает `APPS.LST` из всех корневых `.B22` файлов карты.
Остальные файлы сохраняются. При ошибке подготовки содержимое карты не меняется.
Открытый эмулятор держит образ карты заблокированным, поэтому его нужно закрыть.

Карта по умолчанию находится в
`analysis/emulator/experiments/<SHA-256 загрузчика>/sd-card.img`.
Путь совпадает с выбором обычного окна для этого PS. Для другой карты:

```powershell
.\.venv\Scripts\python.exe -m tools.install_sd_app apps/card_demo.b22asm --card analysis/my-card.img
```

Можно собрать только файл для переноса на FAT16-карту:

```powershell
.\.venv\Scripts\python.exe -m tools.b22asm apps/card_demo.b22asm analysis/DEMO.B22
```

Если копировать файлы вручную, нужно также записать их имена в `APPS.LST`,
по одному имени на строку (ASCII, CRLF или LF). Сейчас автоматическое обнаружение
новых файлов самим телефоном не реализовано; установщик обновляет каталог за него.
Старое имя `APP.B22` тоже допустимо при включении в каталог.
Запуск с физической карты на настоящем телефоне пока не проверен;
нужен и соответствующий изменённый PS.
На текущем этапе окно MMI и адреса функций привязаны к исследованной версии B220.

## Минимальная программа

```text
clear 0x0010
set r0 20
set r1 0xffff
text r0 r1 "MY SD PROGRAM"
wait:
yield wait
```

`clear` заполняет рабочую область цветом RGB565. `text` берёт Y из первого
регистра, цвет из второго и центрирует строку. `yield` возвращает управление
телефону: при следующем событии выполнение продолжится с указанной метки.
Комментарии начинаются с `;`. Строки заключаются в кавычки.

| Команда | Значение |
|---|---|
| `set r0 123` | Записать 32-битное число |
| `add r0 -4` | Прибавить число с переполнением по модулю 2³² |
| `mov r0 r1` | Копировать регистр |
| `jmp label` | Безусловный переход |
| `jeq r0 r1 label` | Переход при равенстве |
| `jne r0 r1 label` | Переход при неравенстве |
| `jlt r0 r1 label` | Переход при знаковом сравнении «меньше» |
| `clear 0x0841` | Залить область 176×176 |
| `rect r0` | X, Y, ширина, высота, цвет из пяти последовательных регистров r0…r4 |
| `text r0 r1 "HELLO"` | Центрированный текст: Y=r0, цвет=r1 |
| `event r6` | Текущее сообщение MMI в регистр |
| `yield label` | Вернуть управление MMI; сохранить адрес продолжения |
| `restart` | Перейти к инструкции 0 без очистки регистров |
| `halt` | Завершить исполнение, оставив последний рисунок |

Регистры — `r0`…`r7`. Для `rect` допустимы начальные `r0`…`r3`.
Координаты прямоугольников обрезаются по границам рабочей области.
Для текста Y=0…156, до 64 печатных ASCII-символов, штатный шрифт 6.
Приложение рисует в области 176×176. При открытии списка и запуске приложения
загрузчик очищает всю клиентскую область 176×196; оставшаяся нижняя полоса —
штатная экранная клавиша выхода. Это устраняет остаток полосы прокрутки от
предыдущего меню, который был виден в первом варианте загрузчика.

У `event` есть именованные константы для сравнения через `set`:
`UP=0xfa01`, `DOWN=0xfa02`, `LEFT=0xfa03`, `RIGHT=0xfa04`, `OK=0xfa1b`,
`OPEN=0xf021`. При перерисовке приходят также сообщения MMI, поэтому программа
должна сохранять координаты в регистрах и уметь снова рисовать экран.
Левая и правая экранные обслуживаются самим загрузчиком.

[Полный пример с движением и границами](apps/card_demo.b22asm),
[вторая программа](apps/card_second.b22asm).

## Нативные программы B22N

Кроме байткода B22V, загрузчик запускает машинный код ARM/Thumb. Это основа
для Java-машины ([J2ME_RU.md](J2ME_RU.md)) и других «тяжёлых» программ.
Нативный код работает без песочницы: ему доступно всё, что доступно прошивке.

Программа пишется на C без libc, интерфейс описан в [patches/b22n.h](patches/b22n.h),
пример — [apps/card_native.c](apps/card_native.c). Сборка и установка:

```powershell
.\.venv\Scripts\python.exe -m tools.build_native_app apps/card_native.c
.\.venv\Scripts\python.exe -m tools.install_sd_app apps/card_native.c --card <образ карты>
```

Установщик принимает `.b22asm`, `.c` (собирает B22N) и готовый `.B22`.
Тип файла загрузчик определяет по сигнатуре; расширение у обоих `.B22`.

* Файл до 1 МиБ: заголовок 32 байта, образ, таблица перемещений.
  Программа компонуется с базой 0; загрузчик берёт память в Dynamic App Heap,
  прибавляет адрес загрузки к перечисленным словам и обнуляет `.bss`.
* Таблицу строит [tools/build_native_app.py](tools/build_native_app.py): программа
  компонуется дважды (база 0 и `0x10000000`), отличающиеся слова и есть адреса.
  Так учитываются и переходники Thumb→ARM, которые `ld.lld` вставляет сам.
* Деление, 64-битная арифметика и плавающая точка — compiler-rt из Zig, собранный
  в режиме ARM (`analysis/toolchains/rt/`); вызовы из Thumb идут через переходники.
* Точка входа `b22n_main(api, message, parameter)` вызывается с `B22N_OPEN` после
  загрузки и затем на клавиши, таймер и перерисовку. Программа получает все
  клавиши, включая экранные: нажатие, отпускание, повтор, долгое нажатие
  (коды в `b22n.h`). Долгое нажатие правой экранной всегда возвращает к списку;
  `api->exit()` — выход из программы.
* Перед выгрузкой (выход, возврат к списку, закрытие окна) программа получает
  `B22N_CLOSE` и должна освободить свою память и закрыть файлы.
* API v1: память (App Heap) и наибольший доступный блок; файлы по ASCII-пути:
  открытие, размер, чтение, позиция (seek), закрытие; заливка и текст;
  кадровый буфер всего экрана 176×220 и вывод изменённого прямоугольника на LCD;
  один таймер окна; миллисекунды с включения; выход.
* `alloc` возвращает 0, если блок не помещается. Сам аллокатор прошивки в этом
  случае перезагружает телефон, поэтому загрузчик заранее обходит пул
  ([Память B220](MEMORY_RU.md)). Все выделения загрузчика идут так же.

Демо проверяет выделение 1 МиБ, чтение `E:\APPS.LST`, данные с указателями
и деление; стрелки двигают квадрат, OK — выход. Проверено быстрыми CPU-тестами
(`tests.test_sd_app`) и полным прогоном итоговой прошивки (`Start B220 CUT.cmd`)
с картой, где лежат DEMO, NATIVE и SECOND.

## Формат и размещение

Заголовок 16 байт, все числа big-endian:

| Смещение | Поле |
|---|---|
| 0, 4 байта | ASCII `B22V` |
| 4, u16 | Версия 1 |
| 6, u16 | Длина заголовка 16 |
| 8, u16 | Число инструкций, 1…256 |
| 10, u16 | Резерв, 0 |
| 12, u32 | Размер области строк |

Далее идут инструкции по 8 байт: `opcode:u8, a:u8, b:u8, reserved:u8=0, immediate:u32`.
Порядок номеров команд 0…13 соответствует `OPS` в
[ассемблере](tools/b22asm.py). Переходы задают индекс инструкции; TEXT — смещение
нуль-терминированной ASCII-строки относительно начала области строк.
После кода идёт область строк. Весь файл — не более 4096 байт.

Нативный [интерпретатор на C](patches/sd_app.c) расположен в ограниченном
ROM-слоте предыдущего эксперимента. Используются 80 из 81 байта прежней доски
Сокобана по `0x04388f50`, а файл получает отдельный буфер штатного аллокатора.
Буфер освобождается перед повторной загрузкой, при возврате в список и закрытии
окна. Каталог имеет отдельный буфер, который освобождается при обновлении/закрытии.
Это отдельный вариант PS; запуск игры «Поймай!» остаётся в своём образе.
Один встроенный фон заменён однотонным JPEG, чтобы выделить место под код.
Уточнение: это картинка теста клавиатуры инженерного меню, а не обои
([Память B220](MEMORY_RU.md)).

Пункт Games использовал функцию `0x60EEE9`, открывавшую меню Сокобана.
Её вход по `0x60EEE8` заменён 8-байтным Thumb-переходом `LDR R3; BX R3`
на нашу маленькую функцию в секции `.launch` по `0x14D001`. Она вызывает
штатное создание окна с дескриптором `0x70D150`,
сразу открывая окно `0x160002` со списком приложений. Окно меню `0x160001`
на этом пути больше не создаётся; дескрипторы остальных игр не меняются.
Указатель на старую функцию также встречается по `0x39D8AC`, однако одной
замены этого указателя оказалось недостаточно: контрольный запуск всё ещё
открывал старое меню. Поэтому используется переход на общем входе функции.

Установленные интерфейсы этого PS, указаны Thumb-указатели:

| Указатель | Вызов |
|---|---|
| `0x5edc5f` | `SFS_CreateFile(utf16_path, 0x31, 0, 0)` → handle, 0 при ошибке |
| `0x5ee59f` | `SFS_GetFileSize(handle, &size)` → 0 при успехе |
| `0x5ee49f` | `SFS_ReadFile(handle, buffer, size, &actual, 0)` → 0 при успехе |
| `0x5ee485` | `SFS_CloseFile(handle)` → 0 при успехе |
| `0x6a5439` | Аллокатор: `(size, 0x44444444, "B22V", 0)` → буфер из Dynamic App Heap. Второй аргумент — тип кучи; прежнее значение 0 перезагружало телефон на запросах больше ~1,6 КБ ([подробнее](MEMORY_RU.md)) |
| `0x6a5469` | Освобождение буфера |

Режим открытия взят из штатных читателей файлов и проверяется реальным прогоном.
Чужой диск не перебирается: загрузчик использует только SD-том `E:`.
Графические вызовы — те же, что в [нативной игре](NATIVE_GAME_RU.md).

## Ошибки и проверка

Загрузчик проверяет заголовок, длины, номера команд и регистров, переходы и строки
перед выполнением. На одно событие разрешено 512 инструкций, затем управление
возвращается в MMI с ошибкой. Окно ошибки показывает номер:

| Номер | Причина |
|---|---|
| 1 | Выбранный файл не открыт: отсутствует файл/карта или ошибка SFS |
| 2 | Не получен размер или он вне 16…4096 |
| 3 | Нет памяти под файл |
| 4 | Ошибка чтения/закрытия или прочитан неполный файл |
| 5 | Неверный формат программы |
| 6 | Выполнение вышло за конец кода |
| 7 | Неизвестная команда при исполнении |
| 8 | Превышено 512 инструкций до YIELD/HALT |

Повторная загрузка — F1, возврат к списку — F2. HALT хранит внутренний статус 9,
ошибкой он не отображается.

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_sd_app tests.test_sd tests.test_catch_game_patch tests.test_ui_label_patch tests.test_firmware_patch
.\.venv\Scripts\python.exe -m tools.prove_sd_app
.\.venv\Scripts\python.exe -m tools.prove_sd_app --compare
.\.venv\Scripts\python.exe -m tools.prove_sd_app --directory analysis/firmware-patches/sd-app/proof-missing --missing --keys soft_left soft_right
.\.venv\Scripts\python.exe -m tools.verify_artifacts
```

Быстрые CPU-тесты используют явно обозначенные синтетические SFS/GUI-вызовы.
Полный прогон загружает PS с двумя файлами на одной карте и использует реальные
SFS, аллокатор, диспетчер MMI и устройства. Инструмент подаёт клавиши и читает
результаты; код, RAM и регистры гостя не подменяет. Фиксируются результат чтения,
SHA-256 буфера, обращения интерпретатора к байткоду и итоговый LCD.

Быстрые проверки: 27 тестов, включая общий вход из Games, выбор двух программ,
прокрутку списка, ошибки каталога и освобождение всех буферов. Образ:
`b9da6a50a6c8a0c66d3f1d7e28107b28949d86aee47519c456a57cfa551eb104`.
Загрузчик и список занимают 3072 байта ROM.

Сценарий полного прогона: прямой вход из Games в список; запуск DEMO.B22,
стрелки, OK и F1; возврат к списку; выбор SECOND.B22; возврат и закрытие окна.
Прогон завершён с **PASS**, 19 нажатий: проверены реальные чтения обоих файлов,
отсутствие окна «Новая игра», освобождение буферов и чёрные пиксели в нижних
20 строках клиентской области при показе приложений.
Исторические проверки предыдущей версии (PS `b991e9439dd6…`) сохраняют свои
отчёты `proof-final`, `proof-second`, `proof-missing`; к новому образу они не относятся.

Локальные артефакты:
[манифест](analysis/firmware-patches/sd-app/manifest.json),
[проверка списка и двух программ](analysis/firmware-patches/sd-app/proof-multi/proof.json),
[сравнение программ в одном прогоне](analysis/firmware-patches/sd-app/comparison.json).
Оригинальные ZIP/PAC/PS/NV и карта обычной прошивки остаются без изменений.

Следующие расширения: обнаружение файлов без APPS.LST, таймер, UTF-16 строки,
файловые операции из программы, затем более полноценная VM и путь к Java.
