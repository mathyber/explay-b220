# Выбор образа и отладчик

В обычном окне появились **«Прошивка…»** и **«Отладка…»**. Это подготовка
стенда к будущим изменениям прошивки. Обычный запуск по-прежнему выбирает
оригинальный PS; его содержимое не изменялось.

## Работа в окне

1. Запустите `Start B220.cmd`.
2. **«Отладка…»** ставит CPU на паузу, в том числе во время загрузки.
   Видны R0–R12, SP, LR, PC, CPSR, текущий режим ARM/Thumb и инструкции
   начиная с PC. «Продолжить» запускает CPU, «1 инструкция» делает один шаг.
3. В поле точек останова введите адреса через пробел, например
   `0x483978 0x394320`, и нажмите «Применить». Пустое поле удаляет все точки;
   максимум — 64. Для Thumb можно указать нечётный адрес: младший бит
   снимается, режим исполнения определяется CPSR, как и у самого CPU.
4. Для чтения памяти на паузе укажите адрес и нажмите «Прочитать 128 Б».
   Доступны NOR `0x00000000–0x007fffff`, RAM `0x04000000–0x043fffff`
   и её зеркало `0x34000000–0x343fffff`, SRAM `0x40000000–0x4000ffff`.
   Весь запрошенный диапазон должен находиться внутри одной области.
   MMIO не показываем как обычную память устройств.

Остановка происходит **перед инструкцией**, без замены её байтов.
Продолжение пропускает текущую точку один раз; повторное попадание в неё
снова останавливает CPU. Телефонные клавиши после срабатывания точки
не возобновляют исполнение. Закрытие окна отладчика само CPU не запускает.
Время ручной паузы не расходует лимит загрузки.

Регистры и память в работающем CPU показывают последнее чтение на паузе;
окно помечает это явно. Шаг — одна машинная инструкция, включая возможный
переход в IRQ. Шага через вызов, watchpoint, изменения регистров/памяти,
GDB-сервера и исходных символов пока нет. Таймеры модели всё ещё считают
переведённые блоки: отладочные остановки и шаги могут менять этот счётчик.
Это не измерение времени реального телефона.

## Отдельный экспериментальный PS

В **«Прошивка…» → «Выбрать PS…»** выбирается отдельный raw PS `.bin`
**того же размера и с той же раскладкой**, что `analysis/extracted/SC*.bin`.
PAC, ZIP, полный 8-МиБ NOR и образы другой сборки сюда не подходят.
Это не универсальный загрузчик любых Spreadtrum-прошивок: модель оборудования
остаётся профилем B220 L7A. Проверка длины и хеширование определяют образ,
но не доказывают работоспособность его изменений.

По умолчанию выбор образа останавливает CPU перед первой инструкцией;
галочку можно снять. Дальше откройте «Отладка…». Выбор и возврат кнопкой
«Оригинал» перезапускают эмулятор. Точки останова сохраняются при перезапуске
в текущем окне, но не между запусками окна и не внутри `.b220state`.

Для каждого SHA-256 окно использует отдельный каталог:

```
analysis/emulator/experiments/<полный SHA-256>/
```

В нём свои NOR, карта FAT16, журналы и кадры. NOR записывается после
достижения контрольной точки загрузки; ранняя отладочная остановка её
не создаёт. Новая SD содержит образцы просмотра. Если выбрать существующую
SD в экспериментальном режиме, окно импортирует **копию** в этот каталог.
Обычная карта и NOR автоматически не переносятся. Изменение PS снаружи
и перезапуск создадут другой каталог по новому хешу; выбор образа не
запоминается после закрытия программы.

Для изменённого PS отключены наблюдатели функций оригинала: MMI-окна,
подсветка, журнал обработчиков клавиатуры, диагностические assertion/power
остановки и milestone. Эти адреса могли перестать обозначать прежние функции.
Модели LCD, KPD, IRQ, памяти, SD и JPEG продолжают работать. Проверки входного
хеша сетевого HLE сохранены; в оконном экспериментальном режиме «Сеть…»
отключена. Аппаратную эмуляцию SIM/модема этот этап не добавляет.

## Консоль

Остановка оригинала перед конкретным адресом:

```powershell
.\.venv\Scripts\python.exe -m emulator.run --explore --instructions 200000000 --seconds 180 --breakpoint 0x483978 --out analysis/emulator/debug/original.json
```

Загрузка отдельной копии и сохранение состояния:

```powershell
.\.venv\Scripts\python.exe -m emulator.run --explore --firmware analysis/experiments/my-ps.bin --breakpoint 0x483978 --save-state analysis/emulator/debug/experiment.b220state
```

Без `--out` отчёт этого режима попадает в каталог хеша. Консоль сама не
подключает SD и не сохраняет отдельную NOR: для них указываются `--sd-image`,
`--load-flash` и `--save-flash`. Эти явно заданные пути выбирает вызывающий;
изоляцию данных автоматически обеспечивает обычное окно. PS-префикс
загружаемой NOR должен точно совпадать с выбранным PS.

Восстановление требует **отдельно выбрать тот же образ**:

```powershell
.\.venv\Scripts\python.exe -m emulator.run --firmware analysis/experiments/my-ps.bin --load-state analysis/emulator/debug/experiment.b220state --instructions 1000
```

Имя файла может отличаться, SHA-256 — нет. Снимок проверяет также профиль,
код модели и версии зависимостей. Старые снимки предыдущей версии эмулятора
потребуют пересоздания. Исходный PS не подменяется содержимым снимка.
Вывод CLI защищён от записи поверх выбранного/оригинального PS,
release NV и оригинальных извлечённых файлов.

Интерактивный CLI дополнительно принимает `--debug-start-paused`,
`--commands <JSONL>` и `--session-status <JSON>` вместе с `--interactive`.
Команды отладчика: `{"action":"debug","operation":"breakpoints","addresses":["0x483978"]}`,
`{"action":"debug","operation":"step"}`,
`{"action":"debug","operation":"inspect","address":"0x04000000"}`;
управление — `{"action":"pause"}` / `{"action":"resume"}`.

## Проверка

Проверены ARM/Thumb, остановка перед инструкцией, шаг, повторное попадание
в точку после продолжения, приоритет точки над диагностическим assertion,
отказ от несовместимых PS/NOR/снимков и защита исходных файлов от перезаписи.
Оконный тест проходит через настоящие кнопки отладчика на изолированной
тестовой копии PS с тремя контрольными инструкциями; чтение памяти и
регистров идёт из выполняемого Unicorn CPU.

Файл копии для теста создаётся только в игнорируемом `analysis/`;
оригинальный PS, PAC и архив не изменяются.
